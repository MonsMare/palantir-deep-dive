# 研究范围与证据规范

## 研究对象

主资料库是 [Palantir Foundry 中文技术文档](https://www.palantir.com/docs/zh/foundry)。用户指定的八个能力域为：

| 能力域 | 官方入口 | 在工程闭环中的位置 |
|---|---|---|
| 数据连接与集成 | [Data connectivity & integration](https://www.palantir.com/docs/zh/foundry/data-integration/overview) | 把外部系统变成可计算、可治理的数据资产 |
| 用例开发 | [Use case development](https://www.palantir.com/docs/zh/foundry/app-building/overview) | 把业务决策需求变成工作流和应用 |
| 分析 | [Analytics](https://www.palantir.com/docs/zh/foundry/analytics/overview) | 探索、解释、验证、传播和回写洞察 |
| 模型连接和开发 | [Model connectivity & development](https://www.palantir.com/docs/zh/foundry/model-integration/overview) | 训练、接入、评估、部署和运营模型 |
| 开发运维 | [Product delivery](https://www.palantir.com/docs/zh/foundry/devops/overview) | 把一组资源打包并跨环境、跨安装交付 |
| 安全 | [Security & governance](https://www.palantir.com/docs/zh/foundry/security/overview) | 在数据、对象、动作、模型、Agent 和 API 上统一施加控制 |
| 本体 | [Ontology building](https://www.palantir.com/docs/zh/foundry/ontology/overview) | 统一企业语义、业务逻辑、动作和权限 |
| 管理 | [Management & enablement](https://www.palantir.com/docs/zh/foundry/administration/overview) | 资源、组织、采纳、治理、支持和用例组合管理 |

官方英文站点的架构中心还把能力分为 AIP、数据连接、模型、Ontology、开发者工具、用例开发、可观测性、分析、产品交付、安全治理和管理赋能。因此，本研究额外纳入 AIP、架构中心、Agents、AIP Logic 和 Apollo，以解释“基于 Ontology 的 AI 智能构造”如何真正进入交付流程。

## 研究方法

1. 先扫读八个入口的站内导航树，建立页面族：概念、教程、配置、API/reference、运维、权限、故障排查和产品交付。
2. 对直接决定工程方法的页面深读：用例生命周期、数据连接核心概念、Pipeline、数据期望、Ontology 核心概念、对象后端、动作、模型目标、安全基础、治理流程、DevOps、AIP 架构。
3. 对连接器、表达式、SDK/API、Widget、评估器等大量叶子页面按“能力族”归纳；它们是实现参考，不应被误读成新的项目阶段。
4. 所有结论优先使用 Palantir 官方页面；中文页面明确提示机器翻译时，以英文架构中心或页面原始概念互相校验。

## 证据分级

- **A 级：**官方架构页、核心概念页、生命周期页，直接支撑平台设计判断。
- **B 级：**官方产品 overview、最佳实践、运维和安全操作页，支撑实施流程与控制点。
- **C 级：**官方 API、连接器、Widget、SDK、FAQ 和示例页，支撑具体实现选择。

## 研究边界

“覆盖所有文章和页面”在工程研究上应理解为覆盖站内页面树和所有能力族，而不是把每个连接器、函数签名和 Widget 属性重复抄写。Wiki 会保留页面族入口和关键证据；若要实现机器可读的逐页 URL/标题/状态清单，可在下一轮以官方导航自动抓取结果补充为 CSV。
