# 数据连接与集成

## 1. 数据接入的定位

数据连接不是把文件搬进平台，而是把外部系统纳入可治理、可观测、可版本化的生产链。Foundry Data Connection 的后台负责连接、认证、调度、编排、同步和监控；开发团队应把更多精力放在数据语义、质量和用例价值上。

## 2. 接入节点与技术选择

| 场景 | 选择 | 适用原理 |
|---|---|---|
| 外部系统允许 Foundry 主动连接 | Direct connection | 平台直接执行连接能力，运营最简单 |
| 网络不允许直接入站，但可部署代理 | Agent proxy | 客户侧反向代理，Foundry 仍执行特性 |
| 数据必须在客户侧运行 | Agent worker | 客户 Linux worker 执行 source feature |
| 周期性全量或文件交换 | Batch sync | 以文件/表为单位同步，适合大多数初始化和常规刷新 |
| 大量变化且希望减少重复计算 | Incremental / CDC | 只处理变化，保留状态或消费 change log |
| 毫秒到秒级业务反应 | Streaming | 端到端各组件都按流设计，最慢环节决定整体时延 |
| 图像、文档、音视频 | Media sync / media sets | 保留媒体对象和元数据，供文档智能、模型和应用使用 |
| SAP 快速发现表结构 | HyperAuto | 通过 schema discovery 自动生成同步、管道和 Ontology 资产 |
| 不想复制大表或媒体 | Virtual table / virtual media | 以虚拟方式访问外部数据，权衡时延、可用性和外部依赖 |
| 既没有标准连接器又有 REST 能力 | External transform / external function | 受 egress、凭证和运行时约束的自定义连接 |

官方连接器页面覆盖数据库、S3/ABFS/GCS、SFTP/FTPS、HDFS、本地目录、SaaS、API、消息和媒体等大量来源。工程上应先按数据特征选择运行模式，再选择具体连接器。

## 3. 推荐实施顺序

### 第一步：建立原始落地层

尽量把源数据原样同步进 Foundry，减少连接阶段的业务预处理。这样可以保留证据、降低源系统耦合，并把变化转移到可分支、可审查的下游管道中。

### 第二步：建设可复用数据产品

用 Pipeline Builder 或代码仓库做清洗、过滤、连接、标准化和派生。项目结构建议清晰分离原始、清洗、输出、文档和测试；transform 尽量小而单一。数据工程本质上应遵循软件工程：DRY、显式类型、依赖管理、代码评审、版本控制和可维护性。

### 第三步：在安全边界内做数据丰富

原始数据一进入平台就应考虑敏感字段、目的限制和保留期限。敏感字段可以在适当的最早阶段通过新的 transform 删除或脱敏，但必须先在分支中验证权限标记不会通过血缘继续传播。

### 第四步：为管道添加质量和健康机制

Data expectations 以代码定义输入/输出要求；失败检查可以阻止构建，避免坏数据流向下游。检查应在开发分支运行，通过 PR 进入受保护分支；失败结果进入 Data Health、构建历史和通知系统。

### 第五步：按业务时延升级数据模式

推荐从 batch 起步。当数据规模或刷新窗口需要优化时改用 incremental；当决策需要低延迟且上下游都能支持时再采用 streaming 或 CDC。不要因为“实时”听起来先进就从第一天为所有数据引入流式复杂度。

## 4. 重要技术原理

- **Raw-as-is：**保留事实来源，业务规则在下游版本化，便于回溯和重算。
- **事务/版本：**纠错应通过新 SNAPSHOT transaction 或分支发布，不直接删除数据集破坏历史。
- **增量状态：**增量 transform 可以持久化内部状态，只对变化处理；状态本身也必须纳入运行与恢复设计。
- **显式类型：**源系统类型不一定可信；ID 通常应使用字符串，避免前导零、格式和整数上限导致关联错误。
- **依赖无环：**循环依赖会破坏构建、血缘和恢复，应在项目结构阶段阻断。
- **健康即产品能力：**新鲜度、延迟、行数、唯一性、范围、完整性和业务规则都应成为可观察指标。

## 5. 交付清单

- Source 配置、凭证/身份、运行时、网络和出口策略。
- 原始数据集、清洗数据集、业务输出数据集。
- 增量/流式策略和重放策略。
- Schema、类型、主键、时间列、去重和连接规则。
- Data expectations、Data Health、告警和维护责任人。
- 项目引用和下游使用边界。
- `/Documentation` 中的来源、字段、刷新频率、SLO、异常处置和变更记录。
