# Ontology 化 AI 方法论验收清单

本清单把设计审查中的质疑点转化为项目验收项。每项都包含问题、检测方式和通过标准。

## 1. 业务价值

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 是否明确要改善哪个决策？ | 阅读用例章程和功能需求 | 能指出用户、场景、决策和动作 |
| 是否有业务结果？ | 检查 KPI 和基线 | 至少一个可量化结果和一个质量/风险指标 |
| 是否有领域 Owner？ | 检查角色矩阵和会议记录 | Owner 能决定语义、优先级和价值 |
| 是否范围过宽？ | 检查用例边界 | 第一版能在一个闭环内交付 |

## 2. 工作流发现

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 是否观察了真实工作而非只访谈管理层？ | 检查访谈、观察、案例记录 | 至少覆盖操作者、审批者、领域负责人和 SME |
| 是否记录例外流程？ | 检查例外清单 | 例外、升级和人工覆盖有明确处理路径 |
| 是否识别隐含规则？ | 对照 Excel、邮件、聊天和人工笔记 | 隐含规则被记录、确认和归属 |
| 是否明确动作后果？ | 跟踪动作到下游系统 | 每个关键动作都有结果和责任人 |

## 3. Ontology 设计

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| Ontology 是否只是表目录？ | 检查对象、关系、状态、动作 | 至少有一个完整对象生命周期和动作闭环 |
| 主键是否稳定？ | 重跑构建并比较对象 ID | 构建不导致对象身份和链接无故变化 |
| 关系是否可计算？ | 检查关系来源和特征使用 | 关键关系能支持查询、聚合或模型特征 |
| 派生对象是否可复现？ | 重新运行数据产品 | 同一版本输入产生相同结果 |
| 权限是否进入模型？ | 检查对象、属性、动作和工具权限 | 用户和 AI 只能访问必要资源 |

## 4. 预测能力

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 是否有预测标签？ | 检查标签定义和生成管道 | 标签有明确结果、窗口、截止时间和缺失规则 |
| 是否有时间快照？ | 检查 `as_of_time` 和历史状态 | 训练特征只能来自预测时点之前 |
| 是否有先行特征？ | 检查特征表和特征文档 | 特征能在结果发生前获得 |
| 是否按时间评估？ | 检查训练/验证/测试切分 | 不使用随机切分掩盖时间漂移 |
| 是否有业务阈值？ | 检查成本、风险和告警策略 | 概率已经转成可执行决策规则 |
| 是否有反馈？ | 检查动作结果和标签回流 | 人工判断与实际结果可用于评估 |

## 5. 数据产品

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 数据产品是否有契约？ | 检查产品文档 | 粒度、主键、时间、来源、质量、权限、SLO 齐全 |
| 散乱资料是否保留原文？ | 抽样追溯抽取字段 | 每个关键事实能回到文件、版本、页码或片段 |
| 重复是否可解释？ | 检查去重指纹和实体匹配 | 同一事实不会被无规则合并 |
| 冲突是否显式？ | 构造两个来源相反的测试案例 | 进入优先级规则或人工裁决，不静默覆盖 |
| 抽取是否经过样本评估？ | 检查黄金样本集和评估结果 | 在代表性文档上达到约定精度和成本 |
| 失败是否可恢复？ | 注入损坏文档、迟到数据和 schema 变化 | 有失败队列、重试、补数和告警 |

## 6. AI FDE/Agent 工程

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| Agent 是否有最小工具集？ | 检查工具白名单 | 只授予完成任务所需工具 |
| 上下文是否可控？ | 检查数据集、文档和对象授权 | 不把整个企业数据默认放入上下文 |
| 修改是否在分支中？ | 查看 Branch/PR/Proposal | 生产资源不被直接静默修改 |
| 是否有执行反馈？ | 检查预览、构建、CI 和评估 | Agent 可观察结果并修正或停止 |
| 是否有人工门？ | 测试高风险 Action | 高风险写操作需审批或二次确认 |
| 是否有调用审计？ | 检查 prompt、工具、参数、结果日志 | 能重建一次 Agent 执行链 |

## 7. 用户采用

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 用户是否在原工作流中使用？ | 观察任务完成路径 | 不需要大量跨系统复制和重复录入 |
| 系统是否减少工作？ | 对比上线前后时间和步骤 | 关键流程耗时或错误率有改善 |
| 是否支持渐进自动化？ | 检查辅助、审批、自动化三种模式 | 用户能先验证建议再扩大自动化 |
| 是否有培训和支持？ | 检查课程、教程和支持队列 | 用户知道如何使用、反馈和升级问题 |
| 是否有采用指标？ | 检查用户和工作流指标 | 采用率、动作完成率和业务结果可追踪 |

## 8. 交付与运营

| 检查问题 | 检测方式 | 通过标准 |
|---|---|---|
| 是否能版本化发布？ | 检查 Branch、PR、产品包和版本 | 数据、Ontology、模型、应用可一起交付 |
| 是否可回滚？ | 演练旧版本和旧模型恢复 | 失败后可以恢复服务和数据一致性 |
| 是否可监控？ | 检查数据、模型、AI、工作流、业务指标 | 生产异常能够及时定位到责任层 |
| 是否可复制？ | 试装到第二个部门/组织 | 输入、依赖、权限和定制边界清楚 |

## 9. 硬性停止条件

以下任何一项未通过，都不应宣称预测或 AI 用例已经生产化：

1. 没有明确预测标签；
2. 没有时间截面或存在未来信息泄漏；
3. 没有关键数据来源和证据链；
4. 没有数据质量失败处理；
5. 没有模型评估和部署生命周期；
6. 没有可执行动作或人工处理路径；
7. 没有动作结果和反馈回流；
8. 没有权限、审计和高风险操作控制。
